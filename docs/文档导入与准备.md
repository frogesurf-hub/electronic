## 本机操作

在项目根目录的 PowerShell 操作；无需启动 PostgreSQL、Agent 或桌面。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-document-tools.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\import-documents.ps1 -Manifest .\.local\document-fixtures\manifest.json
powershell -ExecutionPolicy Bypass -File .\scripts\import-documents.ps1 -Verify .\.local\knowledge\import_detection
```

配置脚本优先寻找项目 Python，其次本机随应用提供的文档 Python。只有满足 PDF/OCR 图片依赖的解释器才写入 `.local/document-import-runtime.json`，不改变 Agent 的 `.venv`、不自动下载。当前复用的版本是 pdfplumber 0.11.9、pypdfium2 5.13.0、Pillow 12.3.0；生成测试 PDF 另用 reportlab 4.4.9。其他机器可自行准备 `requirements-documents.txt` 中的环境，再向配置脚本传 `-PythonPath`。OCR 使用 Windows PowerShell 5 与系统 OCR；本机已具备 `zh-Hans-CN`、`zh-Hant-TW`、`en-US`。

现有检测目录已经生成，生成器不会覆盖非空目录。如需另生成一组检测资料：

```powershell
$documentPython = (Get-Content .\.local\document-import-runtime.json -Raw | ConvertFrom-Json).python
& $documentPython .\scripts\create_document_fixtures.py --target .\.local\document-fixtures-new
```

新生成资料的复核标记默认空，首次导入应得到 3 份可用、2 份待复核；不会自动套用此前更正或复核结果。生成器使用 Windows 宋体／微软雅黑字体。

## 换入自己的资料

建立独立文件夹，放入文件和 `manifest.json`。清单须完整列出本次集合的所有文件；再次导入会重建当前集合，不是逐条追加。例：

```json
{
  "schema_version": 1,
  "collection_id": "business_docs",
  "data_domain": "business_docs",
  "documents": [
    {
      "file": "资料.pdf",
      "doc_id": "DOC-001",
      "title": "实际文档标题",
      "version": "v1",
      "source": "实际提供方或发布来源",
      "valid_from": null,
      "valid_until": null,
      "ocr_review_sha256": null
    }
  ]
}
```

`file` 只能是清单目录内的相对路径。编号、标题、版本、来源必须明确填写，不从文件名或模型猜测。适用日期未知时留 `null`；明确填写时用 `YYYY-MM-DD`，结束日期不包含。同一编号可有多个版本，分别列入不同文件；同一编号／版本不得重复。集合编号和数据域为以小写字母开头的英文、数字、下划线。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\import-documents.ps1 -Manifest .\.local\business-input\manifest.json -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\import-documents.ps1 -Manifest .\.local\business-input\manifest.json
```

`-CheckOnly` 实际解析但不写入集合；OCR 临时图片完成后清理。默认产物目录为 `.local/knowledge/<collection_id>`。可传 `-Target`，末级目录名必须与集合编号一致，且不能与输入资料目录重叠。

## OCR 和复核

- `-Ocr auto`：文字 PDF 读取文字层，无文字层的页面才 OCR；图片始终 OCR。
- `-Ocr always`：PDF 全页 OCR，适合文字与扫描内容混合的资料。
- `-Ocr never`：PDF 无文字层则报错，避免静默漏页；不用于禁止图片 OCR。
- `-Language zh-Hans-CN` 可切换到本机已安装的 OCR 语言。

文字 PDF 页中含图片时给出提示并进入待复核状态，因为图片可能含正文。扫描内容默认待复核，其片段存储但不进入可用关键词索引。打开产物的 `preview.md`，对照其中的原件链接、页码、坐标、表格和文字逐项检查。

普通 OCR 行可在清单对应文档中填写更正，块编号来自该文档的解析 JSON：

```json
"corrections": {
  "P1-B4": {
    "text": "对照原件确认后的文字",
    "note": "说明核对的原件和具体错误。"
  }
}
```

更正保留 `raw_ocr_text`、词坐标、`before_correction_text` 和 `correction_note`，不修改原文件。更正后先重新导入，重新对照预览，再将报告中的 `parsed_sha256` 填到 `ocr_review_sha256`，最后再导入一次。复核标记绑定解析结果、文档版本和来源；任何相关内容变化后旧标记失效，需要重新复核。不能只复制摘要便视为识别正确。

扫描表格只识别连续网格的候选行列，第一行作为候选表头；保留每行原始 OCR 行／词、候选单元格、行位置与表头位置，必须复核。复杂或不连续网格保留 OCR 行与坐标，不宣称已恢复表格结构。当前更正入口仅支持普通 OCR 行；表格单元格错误应先修正输入资料并作为新版本重新导入，不能只改行文字导致单元格与文字不一致。合并单元格、倾斜扫描、多栏阅读顺序等不在当前已验证范围。

## 产物与下游接入约定

| 产物 | 用途 |
| --- | --- |
| `index.json` | schema 2 集合，文档元数据、片段、可用关键词倒排索引 |
| `originals/<摘要>.<扩展名>` | 原文件字节快照 |
| `parsed/<摘要>.json` | 页面、块、词／行／表格及更正记录 |
| `import-report.json` | 文档数、片段数、待复核数、来源与版本、摘要 |
| `preview.md` | 人工核对入口，链接原件并展示逐块位置 |

Markdown/TXT 保留真实行号，页码为 `null`；其字符偏移相对于原文件对应行。PDF 页码从 1 开始，坐标从左上角计算，单位 `pdf_points`；图片坐标对应应用 EXIF 方向后的原图像素，单位 `oriented_image_pixels`。PDF 标题基于字体／版面的提示，不等于精确目录解析；章节无法判断时采用文档标题，并记录 `section_basis`。切片默认最多 1200 字符，可用 `-MaxChars` 在 100～4000 内调整；不跨页混合。

表格行片段会附候选表头，以保留列意义；同时保存 `table_id`、`row_number`、`header_bbox`。表格文字是结构化解析结果，不是 PDF 文件中的原始字节串。OCR 更正后的片段必须经快照中的记录追溯回原件。

下游读取前调用 `validate_collection(folder)`。它验证原件／解析摘要，文档元数据，片段文字与字符偏移，章节／页码／坐标／表格位置，正文覆盖完整性和可用关键词索引。检索只使用 `ready_for_retrieval=true` 的片段，并从其对应文档读取版本、来源和适用日期；命中片段编号需回查解析块，不能作为无原件支持的模型证据。

schema 2 由 `PreparedDocumentSearch` 适配到问答证据；schema 1 的旧集合保留兼容。活动集合由 `.local/knowledge/active.json` 保存编号，一次只检索选用集合。未配置时使用旧演示集合；配置损坏或所选集合缺失时返回错误，不搜索其他集合。公共理解读取当前已校验目录来识别标题和编号。指定标题、编号、版本、适用日期均在检索时过滤；未知标题不会扩展到其他文档。适用起始日期未知的资料不进入指定适用日的检索结果。准备解析需可选 PDF 工具，运行问答读取快照时无需在 Agent 环境重复安装这些工具。

同一资料重复导入片段编号保持稳定；版本或解析更改产生新编号。全部解析和快照验证成功后才原子替换当前 `index.json`，失败时保留上次入口；原件、旧解析快照不删除。需要备份集合时一起备份原件、解析快照及索引。导入生成本机报告／预览失败会返回错误，索引以最终校验结果为准。

文件限制：每批最多 50 份／100MB，单文件最多 25MB，PDF 或多页图片最多 100 页，图片每帧最多 3000 万像素，当前索引最多 8MB。原件、检测资料、运行配置和产物均在 Git 忽略的 `.local/`；代码、生成器与本说明可以提交。DOCX、向量索引及 WPF 导入按钮尚未实现。
