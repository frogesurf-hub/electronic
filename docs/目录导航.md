# 电子杯项目目录导航

这里是一份比赛项目，原助手提供桌面、通信和模型基础，队员提供 SQL 与评估模块。
目前保留来源目录结构，避免移动文件后破坏相对路径。无需额外放入完整队员压缩包。

## 日常开发关注的位置

| 目录 | 作用 | 来源与当前状态 |
| --- | --- | --- |
| `src/Desktop/` | WPF 界面 | 保留原传输，已验收问数／澄清，展示表格、SQL、条件与执行记录 |
| `src/agent_core/communication/`、`core/`、`main.py` | 后端启动、消息接收和调度 | 原传输与新增统一业务编排 |
| `src/agent_core/understanding/`、`sessions/` | 公共理解、校验、澄清与会话 | 比赛新增，已验收澄清后补充时间的真实问数案例 |
| `src/agent_core/retrieval/` | 文档导入、检索与证据问答 | 已验收 5 文档导入及一个真实问答、原文引用案例；资料不足案例也已通过用户验收 |
| `src/agent_core/providers/` | 模型调用接口与 DeepSeek 实现 | 原助手，SQL 模块复用这一份接口 |
| `src/agent_core/sql/` | SQL 生成、检验、执行的服务入口 | 队员，已完成离线验证、真实模型与数据库联调 |
| `database/` | 数据库结构、SQL 检验器、只读执行器、Chinook 建库数据 | 队员，程序和固定资产；实际运行数据在 `.local/postgres/data` |
| `src/agent_core/evaluation/` | 评估程序代码 | 队员，可导入；尚未做当前模型效果评估 |
| `evaluation/` | 评估题目、固定预期结果与历史报告 | 队员，历史报告不是本机新跑出的结果 |
| `src/agent_core/tests/` | 原助手测试 | 检查模型接口、通信、配置等基础能力 |
| `tests/` | 队员测试 | 检查 SQL 与评估模块；保留原路径以读取固定数据 |
| `scripts/` | 安装、启动、验证的统一操作入口 | 比赛迁移新增；优先从这里操作 |
| `docs/` | 迁移记录、接入方案、目录导航及原助手技术文档 | 比赛进度先看迁移记录 |

## 环境与辅助文件

- `.venv/`：Python 环境；`.tools/`：项目内 .NET 等工具；`.cache/`：缓存与当前验证报告；`logs/`：运行日志。都是本机内容，不提交 Git。
- `.env`：本机模型配置，不提交 Git。`.env.example` 是无真实密钥的配置样例。
- `pyproject.toml`：Python 依赖与测试设置；`requirements-dev.lock`：已安装的固定依赖版本；`global.json`：.NET SDK 版本。
- `.gitignore` 排除本机环境、数据和凭据；`.gitattributes` 保留队员原样文件的字节，避免 Git 换行转换破坏来源摘要。
- `tools/`：原助手的 C# 通信诊断工具，与保存本机 SDK 的 `.tools/` 用途不同。
- 根目录的 `ARCHITECTURE.md`、`DESIGN.md`、`MVP_DESIGN.md`、`PROJECT.md`、`ROADMAP.md`、`TECH_STACK.md`、`THIRD_PARTY.md` 是原助手文档。先保留作历史参考，比赛状态以 `PROJECT_STATE.md` 顶部说明和 `docs/比赛迁移记录.md` 为准。
- `database/documents/` 的 5 份旧模拟业务文档本轮用于独立文档问答演示，不能当作 Chinook 的配套口径或实体依据。
- `.local/knowledge/legacy_sales_demo/`：文档导入后的索引和原文快照；入口为 `scripts/import-demo-documents.ps1`，本机产物不提交。片段按真实章节／行号引用，Markdown 没有页码，不编造页码。

## 当前实际跑通的关系

```text
模型验证脚本（scripts/check-model-sql.ps1）
  → 队员 SQLGenerationService
  → 实时数据库结构和 Chinook 语义
  → 当前项目的 DeepSeekProvider
  → 生成参数化 SQL
  → database 中的 SQL 检验器
  → chinook_reader 只读执行
  → 返回金额 127.98，与已知结果相符
```

这是单个已知结构化案例的联调成功，尚未证明完整模型效果。`scripts/check-sql.ps1` 仍可离线复查，不访问数据库或模型 API。
WPF 自然语言问数已接公共理解与澄清，完整问题和补充时间均已返回 127.98。此结论仅覆盖一个已知案例。
模拟文档已导入 5 份；问答走公共理解 → DocumentSearch → DocumentQAService → 引用／依据核验 → WPF 原文引用。源码测试通过，用户已验收张伟经验问答及原文引用，资料不足案例也已通过用户验收。该流程不调用 SQL，不把旧文档口径作为 Chinook 定义；融合仍归 J 的交付范围。
